# App review — October 24, 2026

This review covered the shared earnings and tax engines, SwiftData storage, onboarding, shift history, schedules, templates, Home and Summary, PDF export, reminders, Siri shortcuts, widgets, Live Activities, and project generation. Changes are local and uncommitted; version 1.4.2 / build 8 is preserved.

## Corrections

- **Earnings and overtime:** Future records no longer move earlier work into overtime. Backdated inserts, edits, moves, and deletions recalculate overtime in the affected workweeks. Saved base and night prices are retained during those recalculations. Current rates switch at the exact effective-time boundary. Daily and weekly thresholds can be enabled separately, and the workweek start is configurable.
- **Historical pricing:** Newly saved shifts retain priced time segments, including rate, night, and overtime boundaries. Pay-period allocations use those saved segments after settings change. This fixes the reproduced case where changing a night rule moved $8 of an old shift's premium into the wrong period.
- **Period totals and projections:** Crossing shifts are allocated to the correct period and week instead of counted in full on both sides. An open shift's elapsed earnings also appear in the preceding period when it crosses a boundary. Only one period is current at an exact boundary. Monthly anchors on the 29th–31st remain anchored after short months. Projections include remaining scheduled work, future rate changes, night/overtime premiums, and overnight templates, and count overlapping template/schedule descriptions once.
- **Shift integrity:** Invalid clock-out ranges, empty end selections, future active starts, future completed entries, and overlapping records for the same job are rejected. Concurrent work across different jobs remains supported. Batch clock-outs and due schedules validate before conversion, preventing a later validation error from leaving earlier entries partly converted. Planned stops cap accrual even in a read-only widget snapshot. Scheduled work conflicting with recorded time remains available for correction instead of becoming duplicate income.
- **Save failures:** Shared save handling rolls back failed writes. A real read-only SQLite integration test verifies that a failed clock-out leaves the saved active shift available and no phantom history or pending edits. Editors retain visible errors instead of dismissing after failed saves.
- **Storage and widgets:** Both targets now declare the same App Group in the source entitlements and XcodeGen configuration. An online SQLite backup migrates the app's original store, including committed WAL pages, and preserves the original. A readiness marker prevents the widget from creating an empty shared store first. Widgets open the shared store read-only, respect the earnings visibility preference, reload after writes and shortcuts, reuse one container per timeline, and show an unavailable/setup state instead of sample earnings on failure. CloudKit is explicitly disabled to match the app's local storage behavior. Startup failures offer retry without resetting saved data.
- **Automation:** Scheduled start/stop reconciliation lives at the app root and works across tabs while the app is active, with catch-up when it opens. Reminder offsets carry into the previous hour and weekday. Reminder changes resync automatically, canceled tasks stop obsolete work, and notification authorization is requested only when applicable. Siri actions refresh widgets and Live Activities. Live Activity operations are serialized, and a changing job title replaces the old activity rather than leaving stale attributes.
- **Take-home estimates:** Insurance and retirement reduce estimated cash take-home as well as income-tax wages. Section 125 insurance and traditional retirement deferrals receive distinct FICA treatment. Additional Medicare payroll withholding uses the employer threshold regardless of filing status. Negative paycheck adjustments remain supported, with withholding bounded at zero. Closed-period taxable supplements are annualized from that period's actual allocated amount. The UI identifies the 2026 federal/Colorado tax model. These treatments were checked against [IRS Publication 15](https://www.irs.gov/publications/p15), [IRS Topic 751](https://www.irs.gov/taxtopics/tc751), and [Colorado's 2026 withholding worksheet](https://tax.colorado.gov/sites/tax/files/documents/DR_1098_Colorado_Withholding_Worksheet_for_Employees.pdf).
- **History, editors, and access:** Archived-job history remains editable. Archived supplements and premiums remain in all-time totals, with a stable archive timestamp preventing continued accrual. Numeric input rejects malformed/partially parsed values while accepting localized decimals and grouping. Duplicate same-day rates are rejected. Templates can be deleted and cannot save a zero-duration shift. PDF exports use bounded filenames and separate temporary locations so one export cannot overwrite an existing share.
- **Usability and performance:** Home calculates one dashboard snapshot per tick rather than repeatedly fetching and calculating it for child views. Snapshot reads no longer bootstrap or save data. Summary refreshes periodically and reuses its calculated values. Loading failures do not masquerade as zero earnings. Errors stay visible until dismissed; milestone banners clear consistently. Shared typography supports Dynamic Type, the ticker respects Reduce Motion, cards respect Reduce Transparency, decorative backgrounds are hidden from accessibility, and tab controls fit more comfortably on narrow screens. Actual large-text rendering remains a device check.
- **Build reproducibility:** XcodeGen no longer resets the existing 1.4.2 / build 8 metadata to 1.3 / build 5. A Swift package runs the shared engine and persistence suite directly on a Mac without an iOS runtime.

## Verification limits

Signed App Group provisioning, upgrade migration on an actual installed copy, notification delivery, Siri execution, Lock Screen/Dynamic Island behavior, rendered UI at small widths and accessibility sizes, and PDF visual output still require device/runtime validation. The optional schema fields support lightweight migration, but a shipped user store has not been exercised here.

Older shifts have stored totals but no original priced segments. Their whole-shift totals remain authoritative; partial-period allocations use reconstructed segment weights from available settings, or elapsed-time proration when rates are unavailable. Exact original premium timing cannot be recovered when the historical rules were never recorded. New saves retain that information.

Schedules reconcile while the app is active and catch up at the next opening. The app does not claim continuous background execution. Tax calculations remain estimates using the documented 2026 model.
